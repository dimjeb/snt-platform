# Администрирование платформы

Технические операции на сервере. **На сайте этот документ видит только администратор платформы** (меню «Руководство администратора»). Пользовательская инструкция (`docs/Инструкция.md`, страница «Инструкция») написана для садоводов, казначеев и председателей и консольных команд не содержит. Если в ней написано «напишите администратору платформы» — нужная команда здесь.

Все команды — на сервере, из папки проекта:

```bash
cd /opt/snt-platform
```

---

## Выкатить обновление

```bash
cd /opt/snt-platform && git pull origin main \
  && docker compose exec -T backend python manage.py migrate \
  && docker compose restart backend caddy
```

Потом в браузере Ctrl+Shift+R.

- Перезапускать нужно и `caddy`, а не только `backend`: `Caddyfile` смонтирован в контейнер.
- `./deploy.sh` не использовать: он перезаписывает `Caddyfile` голым `:80` и снимает HTTPS.
- Фронтенд на сервере **не собирать**: собранный `frontend/dist/spa` лежит в репозитории. Если сборка на сервере всё же стёрла его — `git checkout -- frontend/dist`.

## Сайт показывает «Ошибка 500»

```bash
docker compose logs --tail=100 backend
```

## Выдать логины сразу всем членам товарищества

Пользователь видит в инструкции: «Хочу выдать логины сразу всем — напишите администратору платформы».

Сначала на одном человеке, чтобы проверить, что всё работает:

```bash
docker compose exec -T backend python manage.py create_member_accounts \
    --org 'ТСН "Здоровье"' --plot 87 --out /app/creds-87.csv
docker compose cp backend:/app/creds-87.csv ./creds-87.csv
docker compose exec -T backend rm -f /app/creds-87.csv
```

Открыли файл, вошли под этим логином, убедились, что кабинет работает — теперь всем:

```bash
docker compose exec -T backend python manage.py create_member_accounts \
    --org 'ТСН "Здоровье"' --out /app/member-credentials.csv
docker compose cp backend:/app/member-credentials.csv ./member-credentials.csv
docker compose exec -T backend rm -f /app/member-credentials.csv
```

- В файле пароли и персональные данные всех садоводов. Права 600 ставятся автоматически. Передать председателю для раздачи и удалить: `rm -f member-credentials.csv`.
- Не выводить файл в терминал через `cat` — пароли попадут в историю команд.
- Повторный запуск безопасен: у кого учётка уже есть, того команда пропускает.
- Имя организации — как в базе, целиком, в одинарных кавычках.

## Человек не видит своё начисление в кабинете

```bash
docker compose exec -T backend python manage.py diagnose_plot 87
```

Команда пройдёт цепочку **начисление → участок → владение → член → учётная запись** и покажет, где обрыв. ФИО маскируются; полные имена — с ключом `--full`.

## Снять ошибочные пени разом

Одну-две строки пеней казначей удаляет сам кнопкой «Удалить» на вкладке «Начисления». Если ошибочных пеней много (например, у всех стоял неверный срок):

```bash
docker compose exec -T backend python manage.py remove_penalties --dry-run   # посмотреть
docker compose exec -T backend python manage.py remove_penalties             # выполнить
```

- Удаляет все строки «Пени за просрочку».
- Пени, погашенные **из аванса**, — возвращает деньги обратно на лицевой счёт участка.
- Пени, оплаченные **настоящими деньгами**, — не трогает и называет такие участки.
- Исходные начисления не трогает. После снятия пени можно начислить заново кнопкой.

## Пени — каждое утро сами

По умолчанию пени начисляются кнопкой «Начислить» → «Пени за просрочку». Чтобы они появлялись сами наутро после срока — строка в cron:

```
0 6 * * * cd /opt/snt-platform && docker compose exec -T backend python manage.py apply_penalties
```

## Выписку провели до 01.10.2026, и целевые деньги ушли в членские

До 1 октября 2026 года остаток «целевого» платежа уходил в другие начисления участка, если целевого ещё не было.

```bash
docker compose exec -T backend python manage.py fix_earmarked_statements --dry-run   # посмотреть
docker compose exec -T backend python manage.py fix_earmarked_statements             # выполнить
```

- Платёж, ушедший не в ту категорию, не удаляет, а сторнирует отдельной строкой и кладёт деньги авансом «ждёт целевой взнос».
- Общий аванс из этих же платежей тоже помечает «ждёт целевой»; если он уже зачёлся во что-то другое — отменяет эти зачёты.
- Строки, которые казначей разделял вручную, не трогает и называет.
- Повторный запуск ничего не меняет.
- После исправления у участков снова появится долг по членскому. Пени, начисленные до исправления, считались от неверного остатка: снять (`remove_penalties`) и начислить заново.

## Проверить, что ничего не сломалось

На машине разработки (временная база, боевое не трогают):

```bash
scripts/check_postgres.sh      # проверки API на настоящем PostgreSQL
scripts/check_browser.sh       # браузер: страницы рисуются, сценарии проходят
```

На боевом — проверка API строит отдельные данные и откатывает транзакцию:

```bash
docker compose exec -T backend python manage.py check_user_paths
```

## Резервные копии

Вручную:

```bash
bash scripts/backup.sh
```

Каждую ночь сама (один раз настроить):

```bash
sudo bash scripts/install_backup_cron.sh        # каждую ночь в 03:00 по часам сервера
bash scripts/install_backup_cron.sh --status    # что стоит и как прошёл последний прогон
```

Час можно передать числом: `sudo bash scripts/install_backup_cron.sh 19`. Часы сервера — по Иркутску (+08). Журнал — `/var/log/snt-backup.log`.

На Яндекс Диск, в папку «Бэкапы/snt-platform»:

| Что | Файл | Шифрование |
|---|---|---|
| База | `snt-<дата>.sql.gz.gpg` | да, паролем `BACKUP_PASSPHRASE` |
| Загруженные файлы (логотип, фото счётчиков) | `media-<дата>.tgz.gpg` | да, тем же паролем |
| Весь код с историей | `code/snt-platform.bundle` | нет — секретов в нём нет |
| Контекст разработки | `code/КОНТЕКСТ-РАЗРАБОТКИ.md` | нет |

Глубина — две недели (`BACKUP_KEEP_DAYS` в `.env`). Старые копии удаляются только после того, как свежая уже легла на Диск; на Диске они уходят в корзину и ещё 30 дней восстановимы.

### Развернуть из копии

```bash
git clone snt-platform.bundle snt-platform                                          # код
bash scripts/restore.sh snt-<дата>.sql.gz.gpg                                        # база
gpg -d media-<дата>.tgz.gpg | docker compose exec -T backend tar xzf - -C /app      # файлы
```

- Без `BACKUP_PASSPHRASE` базу и файлы не расшифровать никак. Пароль — в менеджере паролей, не только в `.env` на сервере.
- Копия, которую ни разу не разворачивали, — не копия. Проверять восстановление хотя бы раз в сезон.
