# Контекст разработки SNT Platform

Документ для восстановления работы с нуля: новый человек или новый
аккаунт ассистента читает его первым и дальше работает так, как будто
вёл проект с начала. Здесь — то, чего не видно из кода: зачем сделано
именно так, какие правила нельзя нарушать, как выкатывать, что не
доделано.

> Секретов и персональных данных здесь нет и быть не должно. Пароли,
> токены, ключи — только в `.env` на сервере и в менеджере паролей
> владельца. Реестр членов и банковские выписки — только на сервере.

---

## 1. Что это

Многоарендная (multi-tenant) веб-платформа для садоводческих
товариществ (СНТ/ТСН): реестр участков и членов, начисления
(членские, целевые, электроэнергия, пени), приём оплаты (выписка банка,
касса, QR), личный кабинет садовода, отчёты.

- Прод: **snt-platforma.ru**, каталог на сервере `/opt/snt-platform`.
- Первый реальный арендатор: **ТСН «Здоровье»**, ~145 участков,
  банк — ВТБ (выписки .xlsx).
- Владелец и единственный разработчик — председатель/админ. Код —
  GitHub `dimjeb/snt-platform` (ветка `main`).
- Инструкция для людей — `docs/Инструкция.md`, она же страница
  «Инструкция» на сайте (вшивается в сборку фронта).

## 2. Стек и устройство

| Часть | Что |
|---|---|
| Бэкенд | Django 5.1, DRF, simplejwt, PostgreSQL 16 |
| Фронт | Vue 3 + Quasar 2, сборка `frontend/dist/spa` **коммитится в репо** |
| Веб | Caddy (TLS, статика, `/media/`, прокси `/api/` на backend:8000) |
| Запуск | Docker Compose: `db`, `backend`, `caddy` |

Приложения бэкенда: `organizations` (арендатор, реквизиты, логотип),
`accounts` (пользователи, роли), `members` (участки, члены,
совладение), `billing` (периоды, виды начислений, начисления, платежи,
авансы, выписки), `electricity` (счётчики, показания, тарифы, расчёт),
`payments` (кабинет садовода, QR), `reports`, `core` (права, общие
модели, проверочная команда `check_user_paths`).

**Арендатор** определяется заголовком `X-Org-ID` (суперадмин выбирает
СНТ в переключателе) или организацией пользователя. Все вьюсеты —
через `OrgQuerysetMixin`, всё создаётся с `organization=require_org()`.
Любой id из запроса (участок, счётчик, начисление) обязательно
проверяется на принадлежность своему СНТ — такие дыры уже закрывались.

**Роли:** `superadmin`, `chairman` (всё в своём СНТ), `treasurer`
(финансы), `member` (только свой кабинет).

## 3. Деньги: правила, которые нельзя ломать

Единый источник логики разнесения — `billing/allocation.py`
(`allocate()`), им пользуются и выписка, и «Принять платёж».

1. Порядок: конкретное начисление → части по категориям (разделение
   платежа) → категория строки (только эта категория) → иначе все долги
   от старых к новым.
2. **Деньги с назначением (категорией) никогда не уходят в чужую
   категорию.** Целевые не гасят членские и наоборот. Остаток
   становится авансом **с той же категорией** (`PlotCredit.category`).
   Ошибка «целевые деньги погасили членские» уже была и исправлялась
   командой `fix_earmarked_statements`.
3. Деньги без категории — общий аванс, гасит что угодно.
4. `spend_credit` тратит сначала авансы с назначением (только на свою
   категорию), потом общий. Списание = платёж + отрицательная строка
   аванса в одной транзакции.
5. Перенос оплаты между начислениями (`transfers.py`) — только у того
   же плательщика, парой платежей `METHOD_TRANSFER` (−/+).
6. Категория из назначения платежа (`matching.extract_category`):
   «членск» / «целев» / «электр|свет|квт»; если найдено больше одной —
   не определена.

**Начисления:**
- Членский — фикс или по соткам (`ставка × площадь`, округление до
  копейки ROUND_HALF_UP; участки без площади пропускаются и
  называются).
- Целевой — фикс или по соткам; «за участок» или «за члена».
  Совладельцы платят как один человек равными долями (копейка в
  копейку, остаток копеек — первым), доля ложится на первый участок
  члена с `member`.
- Срок оплаты `due_date` + пени `penalty_percent` (20 % по умолчанию):
  **разово**, от остатка долга на момент начисления, одна пеня на
  начисление (`penalty_for` OneToOne). Команды `apply_penalties`
  (можно в cron), `remove_penalties` (возвращает списанный аванс,
  отказывается удалять пени, оплаченные живыми деньгами).
- Массовая смена срока — «Срок оплаты» (все/несколько участков).

**Электроэнергия** (`electricity/services.py`):
- Расход = показание в периоде − последнее показание до периода; потери
  (главный ввод − сумма участков) делятся пропорционально расходу.
- Нет показания — начисляется по среднему, пишется **расчётное**
  показание (следующий месяц считается от него, задвоения нет; если
  настоящее окажется ниже — переплата возвращается авансом).
- Период расчёта — только **месячный**. Месячное начисление
  «Электроэнергия» расчёт **перезаписывает**.
- Поэтому начальный долг за свет при добавлении счётчика кладётся в
  **годовой** период (его расчёт не трогает). Вид начисления с
  категорией «электроэнергия» должен быть **один** на СНТ — расчёт
  ищет его `get_or_create` по категории.

**Выписка:** парсер ВТБ .xlsx (`statement_xlsx.py`) и 1С-текст;
строку можно править только пока она `new`. Известная незакрытая дыра:
удаление выписки через API позволяет загрузить её снова и провести
дважды.

## 4. Выкат на прод — строго так

```bash
cd /opt/snt-platform && git pull origin main \
  && docker compose exec -T backend python manage.py migrate \
  && docker compose restart backend caddy
```
Потом в браузере Ctrl+Shift+R.

- **Никогда не собирать фронт на сервере** (`npx quasar build` там
  стирает `dist` и падает на `marked`). Собранный `frontend/dist/spa`
  лежит в репо — собирать локально и коммитить вместе с изменениями.
- `./deploy.sh` не использовать.
- Если сборка на сервере всё же стёрла dist: `git checkout -- frontend/dist`.

## 5. Как вести разработку

- Любая правка фронта или `docs/Инструкция.md` → локально
  `cd frontend && npx quasar build` → коммит вместе с `dist`.
- **Инструкцию на сайте обновлять в том же изменении**, что и функцию.
- Проверки перед каждым коммитом:
  - `scripts/check_postgres.sh` — API-проверки на временном PostgreSQL
    (порт 55432), сейчас 262 проверки;
  - `scripts/check_browser.sh` — Playwright + Chromium + Caddy, сейчас
    63 проверки (фикстура описана внутри скрипта, сценарии — в
    `tests/render_smoke.py`);
  - перед браузерными — пересобрать фронт, иначе тестируется старый dist.
- Не делать `pkill -f "postgres.*55432"` — убивает собственный shell.
- Тестовые данные — только синтетические. Реальные выписки и реестр
  в репо не попадают; каждый коммит проверять на отсутствие ФИО,
  счетов, паролей.
- Ветка работы: одна feature-ветка → PR → squash-merge в `main`.
  После слияния ветку пересоздавать от свежего `main`.

## 6. Как общаться с владельцем

- Подробно, но без воды; конкретные команды, пути, порты.
- Если что-то не сделано или нельзя — говорить прямо.
- Не подставлять «костыли»: либо нормальное решение, либо честно
  сказать, что прямого пути нет.
- Любое напоминание дублировать событием в Google Calendar.
- Неформально, дружелюбно.

## 8. Открыто / известные дыры

- Удаление выписки через API → повторная загрузка → двойное проведение.
- Председатель через общий `PATCH /organizations/<id>/` может менять
  любое поле организации, включая `is_active`.
- Рядовой член через API может сдать показание по чужому счётчику
  своего СНТ.
- Нет ручного создания разового начисления в интерфейсе.
- `/media/` публичная: фото показаний счётчиков доступны по прямой
  ссылке.

## 9. Восстановление с нуля

Резервные копии каждую ночь в 03:00 делает `scripts/backup.sh` на
сервере (cron) и кладёт на Яндекс Диск в `Бэкапы/snt-platform`: база и
`/media` — зашифрованы паролем `BACKUP_PASSPHRASE`, код
(`code/snt-platform.bundle`, вся история) и этот документ — открыто.
Токен Диска — `YANDEX_DISK_TOKEN` в `.env` на сервере (права
`cloud_api:disk.write`; `GET /v1/disk/` с ним отвечает Forbidden — это
нормально).

1. Склонировать `dimjeb/snt-platform` или, если GitHub недоступен,
   `git clone snt-platform.bundle snt-platform` из копии на Диске.
2. Сервер: Docker + Compose, `.env` по `.env.example` (секреты — из
   менеджера паролей), `docker compose up -d`, `migrate`, затем
   `scripts/restore.sh` для базы и распаковка `media-<дата>.tgz.gpg`
   (команды — в `docs/Инструкция.md`, «Хочу сделать резервную копию»).
3. Новому ассистенту дать прочитать этот файл, `README.md` и
   `docs/Инструкция.md` — этого достаточно, чтобы продолжить с того же
   места.
