# SNT Platform

Платформа управления садоводческим некоммерческим товариществом (СНТ).

Поддерживает несколько СНТ на одном сервере (multi-tenant SaaS).

## Инструкция для людей

**[docs/Инструкция.md](docs/Инструкция.md)** — пошаговая инструкция по принципу «хочешь это — сделай так»,
отдельно для садовода, казначея, председателя и администратора. Всё остальное в этом файле — для разработчика.

## Функциональность

- **Реестр членов и участков** — история владения, общая собственность, импорт из Excel
- **Учёт взносов** — членские и целевые, массовое начисление по всем или по выбранным участкам
- **Электроэнергия** — счётчики, показания, распределение потерь в сети; пропущенные месяцы
  достраиваются расчётным показанием и не начисляются повторно, когда человек вернётся
- **Приём денег без эквайринга** — платёжный QR по ГОСТ Р 56042-2014, разбор банковской выписки
  («1С:Клиент-Банк»), автоматическое разнесение по начислениям, аванс на лицевом счёте участка
- **Онлайн-оплата** — драйверы ЮKassa, Т-Банк, Робокассы, CloudPayments (против песочниц не проверялись)
- **Учётные записи членам** — у каждого свой временный пароль с обязательной сменой при первом входе
- **Кабинеты** — председателя, казначея и члена СНТ; кабинет открывается по связи с членом,
  а не по роли, поэтому председатель-собственник видит и свои начисления
- **Отчёты** — Excel: ведомость задолженностей, квитанции, список членов
- **152-ФЗ** — журнал обращений к ПДн, чистка ПДн из логов, парольная политика, защищённые куки
- **Резервные копии** — шифрованные, на Яндекс Диск, с проверкой восстановления

## Стек

| Слой | Технология |
|------|-----------|
| Backend | Django 5 + Django REST Framework |
| Auth | JWT (simplejwt) |
| БД | PostgreSQL 16 |
| Очереди | Celery + Redis |
| Frontend | Vue 3 + Quasar (PWA, mobile-first) |
| Прокси | Caddy (автоматический HTTPS) |
| Деплой | Docker Compose |

## Быстрый старт

```bash
cp .env.example .env
# Заполнить .env

docker compose up -d
docker compose exec backend python manage.py migrate
docker compose exec backend python manage.py createsuperuser
```

После старта:
- API: `https://your-domain.ru/api/`
- Admin: `https://your-domain.ru/admin/`
- Документация API: `https://your-domain.ru/api/docs/`

## Проверки

```bash
scripts/check_postgres.sh   # 114 проверок API на настоящем PostgreSQL 16
scripts/check_browser.sh    # Chromium проходит путь члена и проверяет, что страницы рисуются
```

SQLite для проверок не годится: он молча игнорирует `select_for_update`, и целый класс ошибок
на нём не воспроизводится. Браузерный набор нужен потому, что белый экран фронтенд отдаёт молча —
API при этом отвечает 200.

`check_user_paths` безопасно запускать и на боевой базе: она строит себе отдельную организацию
и откатывает транзакцию.

## Роли

| Роль | Доступ |
|------|--------|
| `superadmin` | Все организации, системное администрирование |
| `chairman` | Полный доступ к своей организации |
| `treasurer` | Начисления, платежи, отчёты |
| `member` | Свои данные, показания счётчика |

## Расчёт электроэнергии

1. Снимаются показания всех счётчиков за период
2. Считается суммарное потребление каждого участка (текущие − предыдущие)
3. Потери сети = главный счётчик − сумма индивидуальных
4. Потери распределяются пропорционально потреблению
5. Начисление = (потребление + доля потерь) × тариф

При отсутствии показаний — используется среднее за 3 предыдущих месяца.
